# Node HTTP contract fixtures

`node/contracts.json` is the reviewed baseline for exactly 32 retained Node HTTP operation
identities. It is generated by real requests to the executable isolated Node server, not by route
source inspection or hand-authored response data.

## Commands

Run from `apps/server`:

```sh
pnpm contract:check
pnpm contract:capture
```

`contract:check` creates a fresh temporary database and upload directory, captures the operations,
and byte-compares the result with the baseline. A mismatch exits nonzero with instructions; it does
not overwrite anything. `contract:capture` performs the same capture and atomically replaces the
baseline. Review the JSON diff before accepting it. Output is stable two-space JSON with a trailing
newline.

## Isolation and safety

- The runner creates its own `mkdtemp` root. Database and uploads are strictly beneath that root.
- The child receives only `PATH` and the three required synthetic path variables.
- The server listens on an ephemeral loopback port and rejects fixed forbidden ports.
- The child has a global fetch guard. Email and IndexNow adapters are in-memory recorders; no
  external network, email, or IndexNow call is permitted.
- The runner sends `SIGTERM`, awaits clean exit, and removes its temporary root.
- Never point this workflow at another checkout, an existing database, or an uploads directory.

## Stability and normalization

The fixture keeps semantic values, ordering, nulls, status codes, errors, deterministic IDs, and
fixed-clock timestamps literal. Centralized explicit rules normalize only values unsuitable for a
stable or secret-free fixture:

- login JWT: `$JWT`
- authenticated request header: `$AUTHORIZATION`
- signed newsletter tokens: `$NEWSLETTER_TOKEN`
- digest secret header: `$CRON_AUTHORIZATION`
- Multer random basename and URL: `$UPLOAD_FILENAME` and `/uploads/$UPLOAD_FILENAME`
- multipart boundary: `$MULTIPART_BOUNDARY`
- documented synthetic login password in the captured request: `$PASSWORD`

Runtime requests still use the real synthetic JWT, signed tokens, cron secret, password, and
multipart body. No raw secret or credential is written to the fixture. Response headers are limited
to contract-relevant `content-type` and CORS headers; volatile transport headers are omitted.

Extra probes live under `observations` and are explicitly excluded from the 32-operation coverage.
They currently preserve the legacy facts that logout does not revoke its JWT and an unauthenticated
unknown dashboard route is answered by the dashboard auth guard. Multer invalid-type and size-limit
error scenarios are deferred there rather than counted as additional operations.
